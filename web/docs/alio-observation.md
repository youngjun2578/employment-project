# 잡알리오 공고 형식 관찰 (조회만, 수집 아님)

관찰일: 2026-10-13. 사람이 브라우저로 여는 것과 같은 수준으로, 요청 사이에 4초 이상 간격을 두고 순차로 요청했다.
받은 HTML 은 세션 임시 폴더(저장소 밖)에만 두었고 커밋하지 않았다. 기관명과 공고 내용은 옮기지 않고 형식과 구조만 적는다.

## 1. 접속과 robots.txt

| 호스트 | 결과 | robots.txt |
|---|---|---|
| `job.alio.go.kr` | 접속됨. 다만 연결이 자주 끊김(약 50%) | **없음(404)** → 제한 규칙 없음 |
| `opendata.alio.go.kr` | 접속됨(간헐적으로 끊김) | 없음(`/robots.txt` 가 메인으로 302 리다이렉트) |
| `www.data.go.kr` | **접속 불가**. 프록시는 통과했지만 원격 서버가 연결을 끊음(해외 IP 차단으로 추정). 1회 재시도 후 중단 | 확인 불가 |
| `apis.data.go.kr` | **접속 불가**(같은 증상) | 확인 불가 |
| `www.alio.go.kr` (첨부 다운로드 호스트) | **접속 불가**. 이 환경의 네트워크 정책 허용 목록에 없음(프록시 CONNECT 403) | 확인 불가 |

- 요청 수: robots.txt 4건, 목록 1건(+재시도 1건), 상세 10건 시도 → 5건 성공. 실패한 상세는 1회만 재시도했다.
- 로그인 영역, POST 폼, 다운로드 엔드포인트는 요청하지 않았다.

## 2. 페이지 구조

- 목록 `/recruit.do`: 상세로 가는 일반 링크 `/recruitview.do?idx=<숫자>`. JS 나 POST 없이 열린다.
  - `idx` 가 API 의 `recrutPblntSn` 과 같은 번호인지는 ⚠️ 미확인. 같다면 원문 링크 대체값으로 쓸 수 있다.
- 상세 `/recruitview.do?idx=N`:
  - 상단 "공고 URL" 항목에 기관 채용 사이트 링크가 있다.
  - 탭 3개: 상세요강 전체보기 / 전형단계별 채용정보 / 첨부파일 전체보기.
  - 상세요강 항목: 표준직무(NCS), 학력정보, 근무분야, 채용구분, 고용형태, 대체인력여부, 근무지, 급여정보, 채용인원, 우대조건, 채용기간, 등록일.
  - 전형단계 항목: 구분, 선발인원, 응시인원, 결과 확정일.
  - 첨부 항목: 공고문, 입사지원서, 직무기술서, 기타 첨부파일, 미첨부사유.
  - 첨부 항목은 코드 정의서의 `atchType` A/B/C/Z 와 `nonatchRsn` 에 1:1 로 대응하는 것으로 보인다.

## 3. 공고문 본문이 페이지에 텍스트로 있는가 → 없다

- 상세요강은 짧은 구조화 값뿐이다. 표 칸 가운데 가장 긴 것도 19~82자다.
- 응시자격·전형방법 서술문과 공고문 전문은 페이지에 없다. 본문은 첨부 파일에만 있다.
- 숨김 `iframe` 2개는 데이터 제출용이었다(문서 뷰어 아님). 사이트 자체 문서 뷰어는 없다.

## 4. 첨부 형식 분포 (샘플 5건, 확장자 기준)

| 구분 | PDF | HWP | HWPX | ZIP | 합계 |
|---|---|---|---|---|---|
| 공고문 | 3 | 1 | 1 | 0 | 5 (공고마다 정확히 1개) |
| 입사지원서 | 3 | 1 | 0 | 0 | 4 |
| 직무기술서 | 2 | 1 | 1 | 1 | 5 |
| 기타 | 0 | 1 | 0 | 0 | 1 |

- 공고문 5건 중 2건(40%)이 HWP/HWPX 라서 변환하지 않으면 사이트 안에서 볼 수 없다.
- ZIP(여러 파일 묶음)도 있다.
- 표본이 5건이라 비율은 참고용이다.
- 이미지 전용 공고문은 이번 표본에 없었다.

## 5. 첨부 다운로드 방식

- 형식: `https://www.alio.go.kr/download/download.json?fileNo=<숫자>` 를 가리키는 **일반 `<a href>` 링크**(`target="_blank"`).
- 링크에 `onclick`, POST, 토큰 파라미터가 없다 → 마크업만 보면 세션 없이 직접 받는 링크로 보인다.
- 다만 `www.alio.go.kr` 가 이 환경에서 막혀 있어서, 실제로 로그인·리다이렉트·쿠키가 필요한지와 응답 헤더(`Content-Type`, `Content-Disposition`)는 **미검증**이다.
- `download.json` 이라는 이름이라 `Content-Type` 이 파일 형식과 맞지 않을 수 있다. 형식은 매직넘버로 판별해야 한다(2단계 파이프라인에서 대응).
- 페이지에 "전체 다운로드"용으로 보이는 숨김 POST 폼(`pfileForm`)이 있다. 쓰지 않는다.

## 6. 지원 링크 형태 ("공고 URL")

5건 모두 이 칸이 있었다. 형태는 아래와 같다.

| 형태 | 건수 |
|---|---|
| 외부 채용 대행 플랫폼 기관 서브도메인 루트 (`https://<기관>.recruiter.co.kr/`) | 2 |
| 외부 채용 플랫폼의 공고 상세 (`https://<서비스>/announcement/detail/<번호>`) | 1 |
| 기관 홈페이지의 채용 게시판 페이지(`.asp`) | 1 |
| **깨진 값** (`http://,`) | 1 |

- 지원 링크가 공고 단위가 아니라 **기관 채용 사이트 첫 화면**인 경우가 많다. 그래서 "지원하기"를 눌러도 해당 공고로 바로 가지 않을 수 있다.
- 깨진 값이 실제로 있다. WHATWG `URL` 은 `http://,` 도 유효한 URL 로 받아들이므로, 호스트 형식 검사가 필요하다.

## 7. 설계 변경 (이번 커밋에 반영)

1. `mapper.ts` `normalizeUrl()`: 호스트가 정상 도메인/IPv4 인지 검사한다. `http://,`, `localhost`, 점 없는 호스트를 거른다.
2. `mapper.ts`: 첨부 상대경로의 기준 주소를 `https://www.alio.go.kr` 로 바꿨다. `/sample-docs/` 외의 `/` 경로를 사이트 내부 파일로 오해하던 문제도 고쳤다.
3. `attachments.ts`: 첨부 프록시 허용 호스트에 `www.alio.go.kr`, `alio.go.kr` 를 추가했다.
4. (다음 단계) 첨부 형식은 확장자·`Content-Type` 이 아니라 매직넘버로 판별한다. ZIP 은 "열람 미지원"으로 처리한다.
5. (UI 제안, 미구현) 지원 링크가 기관 채용 사이트 첫 화면일 수 있으니 버튼 아래에 "기관 채용 사이트로 이동합니다" 안내를 붙이는 것을 검토한다.

## 8. 코드 정의서(참고문서) 대조

- `www.data.go.kr` 에 접속할 수 없어 참고문서 PDF 를 받지 못했다 → **직접 첨부 필요**.
- `recruit-probe/FINDINGS.md` 의 ⚠️ 항목은 그대로 미확인이다.
- 잡알리오 화면의 항목 구성(4종 첨부 + 미첨부사유, 전형단계별 인원)은 FINDINGS 의 가설 필드(`files[].atchType`, `nonatchRsn`, `steps[]`)와 모순되지 않는다.
